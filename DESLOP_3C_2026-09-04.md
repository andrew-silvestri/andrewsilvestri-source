## 3. Claims: what the pages and the app assert that the code does not do

Checked by a read-only pass over `atlas.html`, `model.html`, the app's UI
strings, the engine (`atlas-app.js`, run headlessly over all 60 scenarios),
the payload (parsed) and the build scripts. **Nothing was changed.** Most
serious first.

1. **`model.html` §2 table "What the model contains" is stale and does not
   sum.** "Power station — One real United States plant" (the payload is
   167 countries, and the same page says so at line 64). District 571 →
   3,332 in the payload. National grid 3,546 → 214 grid nodes (3,546 is the
   Grids *tab*, grids plus districts). Price benchmark 6 → 2,902 market
   nodes (6 benchmarks + 2,896 ports). Behaviour channel 6 → 24. Space and
   weather (21 nodes) absent. The rows sum to 84,258 under the stated total
   86,622. `update_atlas_pages.py` rewrites the phrase "six behaviour
   channels" but not this table.
2. **"Settles in between twenty and fifty steps"** (`atlas.html` lines 24
   and 66). The engine converges on `mx < 1e-5` with a cap of 60 and RESULT
   reports the real count; across the 60 scenarios the range is 5 to 42,
   and 14 settle in fewer than 20 (a single-node push settles in 11). The
   upper bound holds; the lower does not. `model.html` line 134's "sixty"
   cap is correct. `atlas-app.js` line 68's comment "30 to 40" is also
   wrong.
3. **"Calibrated" is unsupported in the repo.** `index.html` (description
   and standfirst) and `code.html` say "calibrated model"; `model.html`
   line 221 cites `calibrate/out/parity_target.json`, which is neither in
   the repo nor in `model-code.zip` (the zip carries `verify_parity.py` and
   `extract_calibration.py`, no output); `atlas-app.js` line 9 cites
   `tests/test_atlas_engine.js`, which does not exist. Scenario inputs are
   normalised from real magnitudes (ONI peaks, fuel shares); nothing in the
   repo compares an output to an observed outcome. The "within about a
   factor of two" sentence survives only in `backups/08022026/build_site.py`.
4. **"Every node holds one measured quantity and names where it came
   from"** (`atlas.html` line 22; app header "Every parameter comes from a
   public data set"). Every node has a `src` string, but 1,142 consumer
   nodes' is "elasticity from literature; size from real demand", all 24
   behaviour nodes' say "a model of where demand is decided, not a
   measurement", 2,896 ports carry a name and a harbour size class and no
   number, and `res` — the one per-node number the engine reads — is a
   per-type assumption (`model.html` §5.2). Overstated.
5. **Demand response never manifests.** 1,142 of the 1,144 negative links
   are consumer→district at −0.009 to −0.011, each paired with a two-way
   district→consumer edge at +0.50; pushing a consumer +1.0 moves its
   district **+0.128**. `model.html` line 158's "consumers use less when
   costs rise" is in the payload and not in any outcome. The mechanism
   itself (sign preserved, relief delivered) holds: NAO +1 → GBR grid −0.205.
6. **`model.html` §4/§5 arithmetic vs code.** Step 2 "(1 − inertia)" is
   `(1 − 0.6·RES)` in code (`atlas-app.js` line 154). The inertia table
   gives single values where the payload holds ranges (event 0.15–0.55,
   consumer 0.18–0.73, station 0.14–0.74). "Grid→district 0.60 fixed" is
   0.42–0.60. "Event→grid log10 of real damage cost": 8,733 of 9,259 events
   are USGS earthquakes with no damage cost.
7. **Minor.** "Starting at the most connected power plant… moves one other
   node" (`atlas.html` line 113): Lake Hargy pushed moves only itself.
   "Reach spans five orders of magnitude": 2 to 77,669 is 4.6. "Every
   position is a real coordinate": the 24 behaviour nodes and the sun sit
   at 0,0. Tab subtitles "2,896 ports and benchmarks" / "34,065
   settlements" sit beside legends that count 3,627 / 35,207.

**Holds:** 86,622 nodes, 197,068 links, 1,144 negative, the layer table,
87 isolated (0.10%), the scenario counts and every widest-reach number,
`reach` in the payload equal to a fresh engine run for all 60, every
scenario with a `basis`; "the threshold changes the view, not the answer"
(`minW` is read only by the painter); the behaviour layer's structure
(840 anatomy entries outside the node arrays, no links; 24 channels wired
to demand); the replay slider replays the first-hit step of the same run.

Five for five, then: each of the five apps' projects carried at least one
claim its code does not support. This one carries the most, and the
largest — "calibrated" — is on the home page.

## 7. Second pass: the three apps, "calibrated", the §2 table

**The three violet apps** are on the site's tokens, Plex and the type
scale, chrome only, by editing `climate-cost/template.html`,
`longevity-quotient/template.html` and `skyline/template.html` and
rebuilding (`lca.py --build`, `build_lq.py`, `build_app.py`; the generator
check holds the shipped files to the templates). The climate-cost globe is
the same dark globe as the atlas, so its stage stays `--sea`; the labels on
it take paper ink (`--sea-ink`, `--sea-dim`, `--sea-acc`), and the five node
colours the scene draws come from `--scene-*` tokens (the palette's tints,
the ones that read on the sea) which the panel's legend also uses, so the
key shows what the globe draws — `scene.js` reads those names now, its one
change. The skyline canvas reads `--acc`/`--cool`/`--ink`/`--dim`/`--rule`
from the tokens; `--cool` is the blue tint there because `style.css` has it
equal to `--acc`, which would have erased the near/far depth. The longevity
chart's bars take the figures' colours (wild brown, captive blue). The
10 px in the climate-cost app was CO₂'s subscript inside a 12 px label
(`sub,sup` at "smaller"); pinned to the floor. Each template carries the
note that its brief pointed at the pre-3a tokens.

**"Calibrated".** The artefact exists: `00 DATA/20 derived/calibration/
parity_target.json` (an identical copy in `01 ARCHIVE/17 Julia Model/
calibrate/out/`), dated 2026-07-28. It records the **7,192-node, 13,826-link
July build**, and it is a parity check — the Python mirror and the Julia
core agreeing node by node — not a comparison of any run against an
observed outcome; `calibration.json` beside it is the extracted input
tables (price-series statistics, country mixes). So the word does not
describe the 86,622-node model in any sense the repository supports, and it
is out of all four places: the home page's meta description and standfirst
now say "a model of the world energy system"; `code.html`'s row is "The
model in Julia — the July 2026 build, 7,192 nodes, with the Python mirror
that reproduces it node by node; the current 86,622-node model is built by
the atlas scripts below" (and the atlas row now says what its 18 files
are); `model.html` §7's parity sentence now says which build the three
commands run, that the check file belongs to that build and is not in the
download, and that the current model has no Julia port and nothing that
compares a run to an observed outcome; `atlas-app.js`'s header no longer
names a `test_atlas_engine.js` that never existed. `model-code.zip`'s own
README table (markets 6, grids 214, districts 571, consumers 1,142, events
526) is the retired build's, and is where the §2 numbers came from.

**The §2 table** was not a join bug in the generator's stats: it was the
July build's README table pasted into `model.html`, with four numbers
regex-patched by `update_atlas_pages.py`'s substitution rules — and one of
those rules keyed `\b214\b` (the old grid count) to `s["grid"]`, which is
grids *plus* districts, the Grids tab, so "National grid" read 3,546. The
other rows (725, 571, 6, 6) matched no rule and stood since July. The
mis-key is confined to that rule: `atlas.html`'s layer table uses the same
sum deliberately, as the Grids layer, and says so. The table is now
generated whole by `model_table()`, one row per kind in the payload
(market split into 6 benchmarks and 2,896 ports by their `src`), the
total asserted equal to `n`; the sources table's "channels matched" is
generated too. The first regeneration also exposed trap 8 again: the
`\b7,192\b` rule rewrote the new §7 sentence's "7,192 nodes" to 86,622;
that rule is gone.
