# Stage 1, second pass: does the beauty project still exist?

8 September 2026. `RESEARCH.md` did Stage 1 for the literature on 5 September.
This is Stage 1 for the data as it now stands, answering the four questions in
`03 RESEARCH/rename-hero/BRIEF_beauty_2026-09-08.md` §3. No design decisions are
made here and nothing outside `beauty/` was touched.

## Verdict

**The project exists and nothing in it is broken. The blocker is not money, it
is a daily rate limit, and the key that lifts it turned out to exist already.**
See the addendum at the end: the fetch is now running keyed, 1,177 of 11,009
species are in, and the finish date is 18 September rather than December.

The per-species cost is exactly what the brief says — $0.001, confirmed against
the live API today, not read back out of the file. The full run is $11.01. But
OpenAlex meters a **daily allowance**, not a balance, and without a key that
allowance is 100 species a day. The dependent variable is 177 of 11,009 species
after today's run. On the keyless tier it finishes in **109 more days**. On a
free account key it finishes in **11**.

Everything else is in better shape than the brief assumed. The Red List table is
already fetched and current (2026-1). Two of the three resumable tables are
complete. The model's verification harness catches every fault it claims to, and
was proven able to report a miss. The projected model is 9,113 species.

Wall time is not the constraint: 99 species took **32.6 s**, 0.33 s each, so

**Recommendation: get a key into the environment before anything else.** It is

There is no mammal, reptile, amphibian or fish row anywhere at species level,

**Projected model size once OpenAlex completes: 9,113 species.** Recomputed

### And the harness was proven able to report a miss

HANDOFF trap 26: a `--break` mode that exits 0 either way is decoration, and
6/6 with exit 0 looks the same as a harness that cannot count. So a seventh
mutation was added that `model_maths()` **cannot** see — `REF_YEAR = 2024` →
`2025`, which the synthetic frame never touches, because it arrives already
transformed:

```
  control: REF_YEAR        MISSED
  6/7 faults caught
  PROBLEM: control: REF_YEAR: the mutant passed the test
  exit=1
```

**The harness fails, non-zero, when a fault goes unnoticed.** The 6/6 is a
measurement, not a constant. (The control was run from a scratch copy;
`break_model.py` itself is unchanged.)

### What `break_model.py` proves it catches, and what it does not

Trap 16's point is that reproducing summary statistics does not pin
coefficients, and this project is the pattern the trap points at. What
`model_maths()` actually does is fit synthetic data built from known
coefficients and assert the estimator recovers them — a direct test of
parameters, not of an aggregate — plus two invariants that hold whatever the
numbers are, plus a cross-check against statsmodels as a second implementation.
The six mutations are the faults a drift check structurally cannot see, because
a drift check calls the same `fit_all()` that wrote the payload.

**What it does not reach, in its own docstring's words: the synthetic frame
arrives already transformed, so nothing `join()` does to build one is covered.**
A wrong log base, a reference year off by one, a filter dropping the wrong
species, the name matching between AVONET and the Red List — none of those is
tested here. The control mutation above landed in exactly that hole, which is
the honest way to read the 6/6.

That gap is the largest untested surface in the project and it is where the
species counts come from. **Stage 2 should decide how `join()` gets covered**;
the count that matters (10,669 of 11,009 AVONET species matched to a Red List
category, 96.9%) is currently asserted by nothing.

Written after the four answers above, which are left as they stood.

**The key existed the whole time.** `RESEARCH.md` §9's "an OpenAlex key has not
been requested" was wrong, and so was §1 of this document for repeating it.
`OPENALEX_KEY` was already in `~/.env`, outside the repo, alongside `IUCN_TOKEN`
and twenty-eight others. Nothing was broken and nothing needed requesting: no
shell in this project had ever loaded that file, and
`fetch_openalex.py:56` reads the environment only.

**That is a silent failure, not a loud one, and it is worth recording.** Unlike
`fetch_iucn.py`, `fetch_openalex.py` does **not** call `netutil.need_key()`. The
key is optional there by design — the script is meant to work keyless — so a
missing *or misnamed* variable does not stop the run. It prints `keyless
($0.10/day, 100 species)` and proceeds at a tenth speed. Eleven days silently
becomes 109, and the only thing that says so is one word on line 68 before the
first call. **Read that word before every long run.** Today's, verbatim:

```
  11,009 species, 177 done, 10,832 to fetch, keyed ($1.00/day, 1,000 species)
```

This is HANDOFF trap 28 in a new coat: an instrument pinned to a slow constant
by something nobody chose. The tell was available and free — the word `keyless`
in output nobody was reading.

### What was actually wrong with `data_notes.md:29`, and why nobody saw it

The line was not a pure record. It carried three figures, and only two of them
named a header:

## Trap candidate for HANDOFF §8 — DRAFT, not landed

*Revision 3, 2026-09-08.* **Nothing in `HANDOFF.md` has been edited and nothing
renumbered**; 32 is a placeholder. It stays a draft until the beauty page ships —
a trap entry written the same day as the bug is a lead, not a fact, which is
trap 14 turned on ourselves.

Revision 2 headlined this as an unlabelled inference inside a measurement
record. That was wrong, and the third correction to the line is what showed it:
**the provenance was sound at all three readings.** The figure was published by
the vendor, quoted accurately, and confirmable from a response header. What was
missing was never a label saying where it came from. It was a statement of what
it priced.

> **32. A rate, ratio or per-unit figure must name its operand in the same
> breath as its value; and a correction that reaches the leaves and misses the
> root has not propagated.**
>
> **Clause one — scope.** `$0.0001` is not a fact until it says *per what call*.
> A rate with no operand named is an unfinished sentence, and **no provenance
> label completes it**. Correctly-quoted documentation about a neighbouring
> operation is indistinguishable from documentation about yours until the
> operand is written down.
>
> *Check:* for every per-unit number in a record, name the thing it prices. If
> that cannot be stated in the same sentence as the value, the figure is not yet
> a measurement.
>
> `03 RESEARCH/beauty/data_notes.md:29` read `filter-only $0.0001`. Every word
> of that is true — it is OpenAlex's published list+filter rate
> (`help.openalex.org/access/example-costs`, $0.10 per 1,000 calls), and
> `X-RateLimit-Cost-Required-USD: 0.0001` confirms it on the wire. It was
> quoted into `RESEARCH.md` §3.2, `beauty/README.md` and `fetch_openalex.py`,
> and the project planned an eleven-day fetch as a one-day fetch.
>
> **The operand was the whole of it.** This project's call is
> `filter=title_and_abstract.search:"..."` — a **search wearing a filter's
> syntax**, because `.search` is full-text. Measured per call from
> `X-RateLimit-Credits-Required`:
>
> | operation | credits | USD |
> |---|---|---|
> | list + filter, no `.search` | 1 | 0.0001 |
> | `filter=…​.search:"…"` — ours | **10** | **0.001** |
> | bare `search=` | 10 | 0.001 |
>
> Both published rates were always right. They price different operations, and
> ours is the expensive one. **A figure can be correct, published,
> header-confirmed, and still wrong to cite**, because it answers about an
> operation you are not performing — and nothing about its accuracy warns you.
>
> **Clause two — propagation.** The correction reached `fetch_openalex.py` and
> `README.md` on 6 September and stopped. `RESEARCH.md` and the source line
> itself still carried the bad figure two days later, and the source was found
> only because someone grepped for the digits while fixing a leaf.
>
> *Check:* on correcting any number, grep BOTH trees for the wrong value **and
> for its words**, and fix **from the earliest occurrence forward**, not from
> the point of discovery. The words half is not optional: `data_notes.md:34`
> said `filter=title_and_abstract.search:"Panthera leo" → 3,459 (stricter,
> cheaper)` — the same claim, no digits in it, invisible to a value grep, and
> the fourth copy.
>
> **Why "from the earliest occurrence forward" is the rule: three passes at one
> line produced three different errors.** 5 September, a correct figure silently
> applied to an operation we do not perform. 8 September morning, an
> over-correction calling it "never read from any header, wrong by a factor of
> ten" — it is published *and* header-confirmed. 8 September evening, the
> measured table above. Each pass fixed the leaf in front of it and left the
> root to be re-derived by the next reader, differently wrong each time. Patching
> at the point of discovery is what makes that possible.
>
> **This is not trap 11.** Trap 11 is drift — a doc describing a state the site
> has LEFT, fixed by running the generator and diffing. Nothing here drifted.
> The line was wrong the day it was written and stayed exactly as wrong; the
> world never moved. Filing this under 11 teaches the wrong check, because
> **diffing against the tree finds nothing — the tree agrees.**
>
> **This is not trap 30 and not trap 14.** Trap 30 is a set of numbers checked
> against each other when one should have been checked against the world; here
> the world *was* consulted and answered accurately about a different quantity.
> Trap 14 says a brief's premises are leads, not facts — this is the level under
> that: the record you check the brief against can be true and still mislead.
> Trap 12's "claims nobody has a motive to check" is wrong in cause: this figure
> was load-bearing and there was every motive.
>
> **Secondary, and it earned its place.** Provenance labelling — `[M]`
> measured, `[C]` computed, `[I]` inferred — is worth keeping in research notes,
> **not** because it would have caught this line (it would not; the figure was
> genuinely published) but because it caught the relapse below. It is a
> convention with no gate behind it: `sitefig.py` enforces the equivalent for
> figures, Markdown enforces nothing, and by trap 17's standard an unenforced
> rule is a claim.

### The line relapsed twice in one day, both times by the pass fixing it

The evidence for the secondary note, and against trusting either clause without
a gate.

1. Annotating line 29 for carrying an unscoped figure, the same pass **added an
   unlabelled derivation to the `[M]` line** — "At $0.001 a search, $1/day is
   1,000 searches", which is arithmetic on the reading beside it, not a reading.
   Caught on review, split onto its own `[C]` line.
2. The same annotation offered "$0.0001 is the price of one credit" as a
   reconciliation. That was a reconstruction, not a reading, and stayed one
   until the header probe measured it. It is now true and measured — a plain
   list+filter really is one credit — but it was asserted before it was known.

**Two relapses, one line, one day, both by the pass written to prevent them.**

### What would convert clause one into a rule

Not to be written now; the decision waits until the beauty page is built.

A check of perhaps fifteen lines: any line in a research note carrying a
currency figure or a `→ number` must state an operand — a per-call, per-species,
per-row noun — in the same sentence. **Two conditions, neither optional:**

1. **Break it first and confirm it FAILS rather than prints** (trap 26). The
   pattern to copy is `beauty/break_log.py`, whose own control run was proven to
   report 2/5 and exit 1 under two deliberate mutations.
2. **Point it at `data_notes.md:29` as it read on 5 September.** If it does not
   flag `filter-only $0.0001` for having no operand, it does not work, and that
   is what has been learned instead.

Note that a *provenance* checker would have passed that line at every reading.
Only a scope checker fails it.

## Observation: a correction pass is a change, and is reviewed less

Recorded 2026-09-08 at Andrew's request. **Not a trap, not numbered, nothing
renumbered** — an observation about the day, kept because five instances landed
inside twelve hours and all of them arrived with the authority of a repair.

A correction is an edit like any other and can introduce error. It gets less
scrutiny than the edit it fixes, because it presents as the thing that makes
something right. Every instance below was applied to a *record* rather than to
code, which is where this is hardest to see: nothing runs, so nothing fails.

| # | the correction | what was actually true |
|---|---|---|
| 1 | the `[C]` relapse — "At $0.001 a search, $1/day is 1,000 searches" added to the `[M]` line | arithmetic, not a reading; correct but mislabelled |
| 2 | "$0.0001 is the price of one credit", offered as reconciliation | a reconstruction asserted before it was measured — later confirmed true |
| 3 | the `[I]` note: "never read from any header, wrong by a factor of ten" | **the figure is published by OpenAlex and header-confirmable** |
| 4 | "your margin priced the spent $1 against prepaid; it is $2.17 not $0.17" | **$10 − $9.83 = $0.17 is right; it priced prepaid alone, as its words say** |
| 5 | "the reset monitor reads the status code, so it cannot detect the reset" | it read `X-RateLimit-Remaining-USD`, which is `0` on a prepaid-funded 200 — already a two-valued signal |

**Two of the five corrected something that was already correct** (3 and 4), and a
third (5) described a mechanism the code did not have. In each case the target
was true and the correction was confident.

### The check that follows

**Before correcting a figure, state what it was a claim ABOUT.** If the original
was right about a different quantity, the fix is to name the quantity, not to
change the number. That is exactly what instance 3 got wrong — `filter-only
$0.0001` needed an operand, not a retraction — and it is the same sentence as
trap 32's clause one, arriving from the opposite direction: clause one says an
unscoped figure is an unfinished claim, and this says an unscoped *correction* is
too.

Instance 4 has its own form of it: a number can be a correct answer to a
different question. `$0.17` prices prepaid alone against the need; `$2.17` prices
the $12 actually bought. Both arithmetic is sound. Only one answers the sentence
that was written.

### Why it belongs with the fetch and not in the traps

Every instance was caught by someone reading the correction as carefully as they
would read new code, which is the only control that worked all five times. There
is no cheap gate here and this document should not pretend there is one. What it
can say is what the day measured: **the correction pass to a research record was
the least reliable work done today**, and the two harnesses written the same day
(`break_model.py`, `break_log.py`) were the most, because both were required to
fail before being believed.
